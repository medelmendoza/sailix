# ADR-0018 — Tala integration via Sailix gateway; offline model
Status: **APPROVED 2026-10-13 (user approved the Tala-only MVP and M1 with conditions; see docs/13 §10)**
**Context:** Tala API facts F1–F10 (docs/13 §2): plaintext HTTP, ids in URL paths, client-side scoring, snapshot sync, download-first offline model.
**Options:** (A) mobile calls Tala directly; (B) Sailix backend gateway (typed thin proxy under `/api/v1/modules/tala/*`); (C) migrate Tala data into Sailix.
**Recommended:** (B). The gateway derives `userId`/`teamId` from the link (never from the request), enforces entitlement/role/tenant status, calls Tala server-side (HTTPS-only, allow-listed platform-configured host, timeouts, bounded retries, redacted logs), validates response shapes, and returns media URLs as Tala provides them. Mobile offline store: `expo-sqlite` with real keys, scoped per user+membership, download-first like Tala, snapshot upload of COMPLETED items via the gateway (manual + on reconnect), wipe on logout/401/suspension.
**Trade-offs:** Gateway code and Tala-availability coupling vs. credential safety and immediate org control. (C) rejected: contradicts reuse of the existing backend/DB and risks production data.
**Security implications:** SSRF prevented (host is platform-level setting, not tenant-supplied); confused-deputy prevented (ids fixed from link); upstream plaintext HTTP is a production blocker until confirmed HTTPS (D-T2); client-submitted scores and on-device answer keys remain (D-T8).
**Consequences:** Contract tests use recorded sanitized fixtures; **no test or build calls production Tala**; verification spike T0 requires explicit approval and a non-production environment.
**M1 implementation note:** `TalaEndpointGuard` (https-only origin, allow-listed host from deployment config, hostname-form checks, every resolved address must be public) and the `RequireModule` middleware (module enabled, role ability, `503 module_unavailable` until an approved endpoint is configured) exist; no HTTP client exists yet. **M3 must:** call `assertSafe()` on every request, connect to a returned address (IP pinning), disable redirects, set timeouts, and never log credentials/tokens.
**Open questions:** D-T1 (not authorized), D-T2 (unconfirmed → production blocked), D-T8 (scores not authoritative; server-side validation to be investigated), sync idempotency/merge semantics (T0).
**M3 implementation note (2026-10-13, read-only):** `TalaClient` (guard + IP pinning + no redirects + timeouts + size cap + one retry for connection errors on GETs; errors carry a category only), `TalaGateway` (ids from the stored link; client-chosen assignment/material ids are looked up in Tala's own answer for that user; quizzes listed but never delivered because their payload carries the answer key; EPUB/legacy quiz omitted; only https addresses passed on), `ExternalAccountLinker` (identity-level claim/release, in `App\Identity`). Endpoints under `/api/v1/modules/tala/*` behind `tenant.context` + `module:tala`; link is throttled (5/min/user). Offline store and score submission are NOT built (docs/13 §18).
**Offline/progress note (2026-10-13):** structured offline store is AsyncStorage JSON (no tokens/credentials), files in the app sandbox via `expo-file-system`; progress submission built behind `SAILIX_TALA_PROGRESS_WRITES` (default off) pending the production write test (docs/13 §20).
